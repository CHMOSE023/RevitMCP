# 失败之后怎么办

第一个问题永远是：**这次调用到底执行了没有。**
答错了这个问题，补救动作本身就会造成损坏——最典型的是超时后直接重建，
于是模型里多出一整套重复构件，而它们和原来那套长得一模一样。

---

## 按错误码

| 错误码 | 执行了吗 | 怎么办 |
|---|---|---|
| `INVALID_PARAMETER` | **没有**，整批未执行 | 报错里指到了具体是哪一项、哪个字段，照着改再来 |
| `ELEMENT_NOT_FOUND` | 没有 | ID 不对，或文档换了导致 ID 作废——先 `revit_list_documents` 看看现在的活动文档是谁 |
| `WRONG_DOCUMENT` | **没有，两个文档都没动** | 你的 `expectedDocumentId` 和当前活动文档对不上。**别改这个参数去迁就现状**——先确认到底该改哪个文档，需要的话用 `revit_open_document` 激活它，然后**重新查一遍构件 ID** |
| `WRITE_DISABLED` | 没有 | 用户没开「修改模型」，或排队期间关掉了。请用户打开，你打不开 |
| `CONFIRMATION_REQUIRED` | 没有 | 影响面超过阈值。看清楚影响多少个再带 `confirm: true`，不要条件反射地加 |
| `REVIT_BUSY` | **还没开始**，可以放心重试 | 主线程被占（用户正在 Revit 里操作）。等一下重试 |
| `TIMEOUT` | **不确定** | 见下面「超时」。报错文本里有 `operationId`，拿它去查 |
| `IDEMPOTENCY_CONFLICT` | **没有** | 同一个 `requestKey` 配了不同参数。换一个键 |
| `OPERATION_IN_FLIGHT` | 上一次还在跑 | 别另发一次，用 `revit_get_operation_status` 查它 |
| `TRANSACTION_FAILED` | 已回滚（事务保证） | 但如果同一次调用里有落盘/导出这类外部副作用，那部分**不会**被回滚 |

## 超时

工具明确区分了两种情况，先看错误码本身：

- `REVIT_BUSY`：工作**尚未开始**就被放弃了，模型没被碰过 → 重试。
- `TIMEOUT`：已经开始执行，结果不明 → **先查证，再决定**。

### 查证：先问服务，再查模型

1. **`revit_get_operation_status`**，用超时报错文本里给的 `operationId`（写工具的回执里也有）。
   回执里的 `nextStep` 直接告诉你能不能重试：
   - `committed` → 已经建好了，别再建一次，构件 ID 就在 `affectedElementIds` 里；
   - `rolledBack` / `failed` → 模型原样，可以重来；
   - `unknown` → 服务也不知道，进入第 2 步。
2. **查模型**：`revit_get_model_changes`（带上更早的 token），
   或按类别 + 位置 `revit_query_elements` 查那批东西在不在。

**状态查不到 ≠ 没发生过。** 操作日志只保留最近 200 次调用或 24 小时，
Revit 重启后清空——这几种情况下模型里都可能躺着那次操作的成果，一律走第 2 步。

确认没建 → 重来。确认建了 → 接着往下做。**查不清楚就如实报告不确定**，
保留现状交给用户判断，不要赌。

### 更省事的办法：一开始就带 `requestKey`

所有写工具都收一个可选的 `requestKey`（自己取个本次任务内唯一的字符串）。
**同一个键 + 同样的参数只会真的执行一次**：超时后原样重发，
服务会把上次的回执还给你，而不是再建一遍。

```
第一次：create_line_based_elements { requestKey: "walls-L1", elements: [...] }  → TIMEOUT
重  发：create_line_based_elements { requestKey: "walls-L1", elements: [...] }  → 上次的回执（标注"这是重放"）
```

三条注意：

- 键相同、参数不同会被拒绝（`IDEMPOTENCY_CONFLICT`）——那通常是键被复用了，换一个。
- 上次就失败的键，重发仍然返回那次失败；要真的重来请换一个键。
- 保留期同上（200 次 / 24 小时 / 进程重启清空），**跨重启就别指望它**。

批量创建这种"重复了最难发现"的调用，建议一律带上它。

## 对话框

回执里出现"Revit 弹出了本服务认不出来的对话框"：

- 这一步**多半没有完成**，模型保持原样（工具选择取消而不是替你点确定）。
- 回执里有 `DialogId`。如果这个对话框确实是安全的、而且必经，
  正确做法是把它加进服务端的白名单，而不是让用户长期打开 `autoConfirmUnknownDialogs`。
- 换一种不触发它的做法通常更快。

## 被自动忽略的警告

创建类工具的回执里会有「Revit 警告已自动忽略：…」，带构件 ID。
**不要当噪音**，尤其这几类：

- 「…重叠」「…重复」「完全相同」→ 几乎总是位置错了，去量几何。
- 「多余的房间」→ 同一封闭区域放了两个房间。
- 「高亮显示的图元…」→ 点开 ID 看看是不是你刚建的那批。

## 缺东西

| 缺什么 | 怎么办 |
|---|---|
| 缺族（门窗、标记、家具） | `revit_load_family` 载入。**别降级用别的族凑合而不说明** |
| 缺类型规格（要 250 厚的墙，只有 200） | `revit_duplicate_type` 从相近的复制一个，改厚度。新类型会永久留在项目里，别为一次性建模随手创建 |
| 缺标高 | `revit_create_datums` 建，默认连楼层平面一起建 |
| 缺视图族类型 | `revit_list_view_family_types` 看有哪些，别猜 ID |
| API 根本不支持（原生楼梯、栏杆） | 见 version-limitations.md。可以用替代构件，但必须在交付说明里写清楚 |

## 中断后继续

保留一份紧凑的任务记录，够接着干就行：

- 目标文档路径 + Revit 版本
- 坐标原点与关键尺寸假设（哪些是图上标的、哪些是估的）
- 已完成阶段、关键构件 ID（不是全部 ID，是"这批墙是 333538–333546"这种）
- 结果不明的操作
- 未决问题

**不要**把整个参数表抄进记录，**不要**记令牌。
继续之前先重新核对活动文档——记录里的 ID 只在那个文档里有效。
