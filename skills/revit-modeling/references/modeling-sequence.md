# 建模顺序与批次

顺序的依据是**依赖关系**，不是一套人人都要走的线性流程。
判断"下一步能不能做"的方法只有一个：**它依赖的东西已经建好并且量过了吗。**

---

## 依赖图

```
标高 ─┬─→ 墙 ─┬─→ 门窗（必须有宿主墙）
      │       └─→ 房间（依赖墙围成闭合区域）
      ├─→ 柱（顶到标高）
      ├─→ 楼板 / 屋顶
      └─→ 平面视图 ─→ 立面标记 ─→ 立面
轴网 ─────────────→ 尺寸标注（标注轴网间距）
构件 ─→ 标记（标记依赖被标记的构件在该视图里可见）
视图 ─→ 取景 ─→ 图纸 / 导出
```

几条容易踩的：

- **立面依赖平面视图**：Revit 的立面是"画在某张平面上的立面标记 + 挂在它方向槽上的视图"。
  没有平面视图就建不出立面。
- **房间依赖围合，不依赖楼板**：墙接不上，房间面积就是 0，和有没有板无关。
- **标记依赖可见性**：构件在那个视图里被裁掉或隐藏了，标记就建不上。
- **图纸依赖视图已取景**：先收取景再上图纸，否则视口尺寸算出来是按未收紧的范围。

---

## 任务分支

不是所有项目都从标高开始。

| 任务类型 | 从哪儿开始 | 注意 |
|---|---|---|
| 从参考图建新模型 | 环境 → 基准 → 主体 | 图上没标的尺寸按图估，**在交付说明里写明哪些是估的** |
| 在已有模型里加东西 | 环境 → **复用现有基准与类型** → 主体 | 不要新建重复的标高/类型。先 `revit_list_levels` / `revit_list_types` 看有什么 |
| 改造 / 局部修改 | 环境 → 查到要改的构件 → 改 | 先 `revit_list_phases` 看阶段，否则"现有"和"新建"会混在一起统计 |
| 只出图 | 环境 → 视图 → 取景 → 图纸 | 不碰模型几何 |
| 审计 / 检查 | 只读工具即可 | 别为了查询去改模型（包括别切活动视图） |

## 批次大小

一次调用建多少个，权衡三件事：

1. **回滚范围**：批量是全有全无的。50 面墙里第 47 面参数错了，前 46 面也不会留下。
2. **超时**：一次调用有时限，几百个构件可能跑不完。
3. **回执体积**：每个构件一条回执，几百条会把上下文撑大。

实践：

- **同一依赖阶段的同类构件一次建完**——一圈墙就该一次调用传完，
  不要逐面调用（逐面调用在撤销栈里是 N 步，用户撤不干净）。
- **首次用的组合先建 1 个**量准了，再把剩下的一次性建完。
- **有宿主依赖的后续构件**（门窗、标记）等前置结果核验后再建。
- 几百个同类构件时分批，每批控制在几十个量级。

## 关于"先问还是先做"

只在**影响任务正确性、或错了要大量返工**的关键信息缺失时才停下来问。例如：

- 要建的到底是哪个文档（这个必须确认，不能假设）；
- 参考图上主体尺寸相互矛盾（照哪个建，结果完全不同）。

其余的次要选择**采用明确记录的假设继续做**，在交付说明里列出来：

- 图上没标的细部尺寸 → 按比例估，说明"估算"；
- 材质、类型规格没指定 → 用样板里相近的，说明用了哪个；
- 参考图是透视照片没有可靠比例 → **不要**把目测当精确尺寸，说明这一点。

每个阶段都停下来确认一次，比不问更糟。
