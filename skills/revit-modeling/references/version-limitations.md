# 版本与已知限制

**先看这里再写补救代码。** 对着一个已经修好的 bug 写绕行方案，比不知道这个 bug 更浪费时间。

> 最后更新：2026-09-20，对应 RevitMCP 的 M10-D / M10-E。
> 验证环境：Revit 2019 中文版。2020–2024 只验证了编译，没有跑真实模型。

---

## 已修复——**不要再绕**

下面这些在 2026-09-20 之前是真实存在的坑，现在已经修了并在 Revit 2019 上实测通过。
如果你的记忆或别处的笔记里还留着这些绕行办法，**删掉它们**。

| 曾经的坑 | 现在 |
|---|---|
| 楼板忽略 `levelId`，全落在项目零高程 | 已修。竖向偏移写完读回来核对，对不上整批回滚；回执给 `elevationMm` |
| 曾经要靠"建完再用 `set_element_parameters` 把偏移改回 0"补救 | **不需要了**，这么做反而多此一举 |
| 柱的 `baseOffset` 被丢掉 | 已修，显式写入并核对 |
| `viewType: "elevation"` 必然失败 | 已修，改用立面标记；`revit_list_view_family_types` 可以查族类型 ID |
| 房间标记建不出来（报"缺标记族"，其实是 API 路径错） | 已修，房间/空间/面积走各自的专用 API |
| 参数写入在项目单位与内部单位之间静默回退 | 已修，改为显式 `valueMode`，写不进去直接报错 |
| 缺族只能请用户手工载入 | 已有 `revit_load_family` |
| 导出的图大片空白、没有取景控制 | 已有 `revit_set_view_extent`（三维含剖切框、可隐藏基准） |
| 房间高度只能是 2438.4 | 已有 `upperLimitLevelId` / `limitOffsetMm` |
| 图纸越界只查视口中心 | 已修，按整个外框查，并报视口重叠 |

## 仍然存在的限制

| 限制 | 影响 | 怎么办 |
|---|---|---|
| **没有原生楼梯 / 栏杆** | 建不出真正的楼梯对象 | 可以用楼板拼踏步、幕墙做栏板**并在交付说明里写明**：明细表里它们是楼板和幕墙，不是楼梯 |
| **天花需要 Revit 2022+** | 2019–2021 上 `OST_Ceilings` 建不了 | 工具会明确报错，别反复试 |
| **带洞轮廓（≤2021）** | 洞是建完之后单独开的 `Opening` 构件 | 按类别查楼板时看不到洞；`revit_list_categories` 也列不出"楼板洞口剪切"这个类别，要用 `revit_query_elements` 直接查 |
| **`revit_get_sheet_contents` 不列明细表** | 图纸上的明细表在 `viewports` 里看不到 | 要确认明细表在不在图纸上，查 `OST_ScheduleGraphics` |
| **逃生舱默认关闭** | `revit_execute_script` / `revit_invoke_api` 用不了 | 这是有意的。先找专用工具；确实需要时请用户改配置并重启 Revit，别把它当常规手段 |
| **认不出的对话框会取消操作** | 某些流程可能因此中断 | 回执里有 `DialogId`，反馈给维护者加白名单，而不是长期打开 `autoConfirmUnknownDialogs` |

## 跨版本注意

| 版本 | 差异 |
|---|---|
| 2019–2021 | 楼板走 `NewFloor`（旧 API），带洞轮廓不支持；天花建不了 |
| 2022+ | 楼板走 `Floor.Create`，原生支持多环轮廓；天花可建 |
| 全版本 | 屋顶只能事后开洞（`NewFootPrintRoof` 没有多环重载） |

上面这些差异工具内部已经抹平了（Compat 层），你按同一套参数调即可——
列在这里是为了让你看懂回执里那句"本版本的 API 不支持带洞轮廓"不是错误。

## 这份文件怎么维护

每修好一个坑，**从"仍然存在"挪到"已修复"并注明日期**。
不挪的后果是 Agent 永远在执行不必要的补救动作——
那比留着 bug 更难发现，因为一切看起来都在正常工作。
