# 用 RevitMCP 建模

这份指引管的是**怎么用这套工具把模型建对**，不是每个工具怎么调（那在 `tools/list` 的 schema 里，
写得比这里细）。它要解决的是 schema 说不了的事：先做什么、依赖谁、怎么判断真的做成了。

**为什么需要它**：这套工具的失败模式不是"调用报错"，而是**调用成功、模型不对**。
两轮真实建模实测里，最费时间的四个问题全部是"回执漂亮、警告为 0、几何是错的"。
下面每一条规则都对应其中一次翻车。

---

## 开工前的三件事

1. **确认在改哪个文档。** `revit_get_document_info` 拿到 `pathName`，
   之后**每个写调用都带 `expectedDocumentId`**。
   活动文档会在两次调用之间变：用户点了另一个窗口、你自己的一次另存换掉了当前文件。
   不带它，你会在别人的模型上建完一整层楼才发现。

2. **确认写入开关开着。** `writeEnabled` 为 false 时所有写工具直接被拒。
   这是用户在 Revit 面板上的开关，你打不开——直接请用户切到「修改模型」。

3. **摸清可用的料。** `revit_list_levels`（建模的 `levelId` 全从这儿来）、
   `revit_list_types` 挑规格（墙厚由类型决定，改不了）。
   样板里没有的族用 `revit_load_family` 载入，**不要**因为缺族就降级成"用别的族凑合"
   而不说明。

## 八条硬规则

### 1. 先建一个代表实例，量准了再批量

第一次用某个族类型、某组参数组合、某个版本没验过的路径时，先建**一个**，
`revit_get_element_geometry` 量回来，对了再把剩下的几十个一次性建完。

批量创建是全有全无的，一次调用建 50 个和建 1 个的失败代价完全不同；
而"参数写了没生效"这类问题只有量几何才看得出来。

### 2. 按实际结果验收，不看 isError

`isError: false` 只说明 Revit 没拒绝，不说明东西在对的位置上。每一类构件的验收动作
见 [references/validation-checklist.md](references/validation-checklist.md)，最常用的三条：

- **墙**：一圈墙的合并包围盒 == 图纸外轮廓尺寸。大了一个墙厚就是定位线方向反了。
- **楼板/柱**：回执里的 `elevationMm`、`baseOffsetMm` 与图纸标高对得上。
- **房间**：`areaSqm > 0`（为 0 就是没围合），`unboundedHeightMm` 不是 2438.4（那是默认值，说明上限没设）。

### 3. 区分"省略"和"明确给 0"

省略 = 随默认；给 0 = 我要它正好贴在标高上。两者在工具里是不同语义，
你也要在脑子里分开：想要"顶面正好在标高上"就显式写 `baseOffset: 0`，别靠省略碰运气。

### 4. 单位：几何毫米，参数看 valueMode

所有几何入参一律毫米。但**通用参数写入不是**——`revit_set_element_parameters` 这类
按项目显示单位解释（`valueMode` 默认 `projectUnits`），确实要传 Revit 内部单位
（长度英尺、角度弧度）时必须显式 `valueMode: "internal"`。
别因为建墙用毫米就推断所有参数都是毫米。

### 5. 失败之后先判断"到底执行了没有"

- `INVALID_PARAMETER` / `WRONG_DOCUMENT` / `CONFIRMATION_REQUIRED` → 没执行，改了参数直接重来。
- `REVIT_BUSY` → 还没开始，可以重试。
- `TIMEOUT` → **结果不确定**：拿报错里的 `operationId` 调
  `revit_get_operation_status`，看 `nextStep` 怎么说，**禁止直接重建**。
- 回执里出现"认不出来的对话框"→ 这一步可能没完成，去核对模型。

**批量创建一律带 `requestKey`**（自己取个唯一字符串）：同键同参只会真的执行一次，
超时后原样重发就能拿回上次的回执，而不是再建一遍。

逐条见 [references/recovery-guide.md](references/recovery-guide.md)。

### 6. 替代构件必须说明

用楼板模拟踏步、幕墙模拟栏杆、文字注释代替房间标记——这些都可以，
但**交付时必须说清楚它的类别和工程语义不是真的那个东西**。
明细表里它是楼板，不是楼梯。不要用外观近似宣称完成。

### 7. 查询节制

类型、标高、族这类目录信息在一个文档里查一次就够，自己记住。
`nameContains`、`limit`、`category` 能缩小范围就缩小。
文档一换（回执里会有切换提示），**之前所有 ID 全部作废**，必须重查。

### 8. 出图前先取景

未收过的视图导出来多半是空白——标高线延伸得很远，建筑只占一角。
`revit_set_view_extent` 收到构件上再 `revit_export_image`。
实测同一个三维视图：收紧前有效内容占 1.25%，收紧后 51%。

## 建模顺序

依赖关系，不是流水线。已有模型的改造任务不必从头走，但**依赖仍然成立**：
门窗依赖宿主墙、房间依赖围合、注释依赖视图。

| 阶段 | 做什么 | 进入下一阶段的条件 |
|---|---|---|
| 1 环境 | 核对文档、版本、写开关、现有标高与类型 | 目标文档确认；缺的族已载入或已记录 |
| 2 基准 | 标高、轴网 | 高程与层高对得上图纸 |
| 3 主体 | 墙、柱、梁、板、屋顶、洞口 | **代表实例量过**，包围盒与标高正确 |
| 4 附属 | 门窗（依赖墙）、房间（依赖围合）、栏杆楼梯 | 宿主正确、房间全部 `isBounded` |
| 5 出图 | 视图、取景、注释标记、明细表、图纸 | 标注读数正确、视口不越界 |
| 6 交付 | `revit_get_warnings` 归零或逐条解释、保存、说明未完成项 | 保存的是对的文档，产物可核验 |

分支与批次大小见 [references/modeling-sequence.md](references/modeling-sequence.md)。

## 收尾

- `revit_get_warnings`：归零，或每一条都能解释为什么可以留着。
- 保存：`revit_save_document` 不带 `confirm` 先看清要覆盖哪个文件，再带 `confirm: true`。
  **MCP 建的东西在保存之前只活在内存里。**
- 交付说明里写清楚：用了什么替代构件、哪些尺寸是估的、什么没做。
